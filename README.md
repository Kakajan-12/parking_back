# Atlas Migration Guide

This project uses **Atlas** for database schema migrations. Atlas is a modern tool for managing database schemas as
code.

## Prerequisites

* Go 1.16+
* PostgreSQL database
* Atlas CLI installed

## Installation

Install Atlas CLI:

```bash
  curl -sSf https://atlasgo.sh | sh
```

Or using Homebrew (macOS):

```bash
  brew install ariga/tap/atlas
```

## Project Structure

```
.
├── generatemigration.go    # Go script to generate SQL schema
├── schema.sql             # Generated SQL schema (ignored in git)
└── migrations/            # Directory containing migration files
    ├── 20240101000000_initial.sql
    └── atlas.sum          # Migration checksum file
```

## Workflow

### 1. Generate Schema

Run the Go script to generate the SQL schema:

```bash
  go run generatemigration.go > schema.sql
```

### 2. Create a New Migration

To create a new migration based on schema changes:


```bash
  atlas migrate diff initial --env local
```

### 3. Check Migration Status

```bash
  atlas migrate status --env local
```

### 4. Apply Migrations

```bash
 atlas migrate apply --env local
```

### 5. Generating new migration
```bash
atlas migrate diff add_commits --env local
```

### 6. Push new migration
```bash
atlas migrate push app --env local
```

## Environment Variables

Set your database connection string as an environment variable:

```bash
  export DATABASE_URL="postgres://change_this:change_this@127.0.0.1:5432/parking?sslmode=disable"
```
 
## Common Commands

```markdown
* `atlas migrate diff [name]` - Create a new migration
* `atlas migrate apply` - Apply migrations to database
* `atlas migrate status` - Check migration status
* `atlas migrate lint` - Lint migration files
* `atlas schema inspect` - Inspect current database schema
* `atlas migrate down --dir "file://migrations" --url $DATABASE_URL --dev-url "docker://postgres/17/dev?search_path=public"` - Revert the last applied migration
* `atlas migrate down [N] --env local` - Revert the last N applied migrations
* `atlas migrate down --all --url $DATABASE_URL` - Revert all applied migrations
* `atlas migrate down --dry-run --url $DATABASE_URL` - Preview revert steps without executing  
* `atlas migrate apply --env local` - Atlas migration apply from "atlas.hcl" file
* `atlas migrate hash` - To re-hash the contents
```

## Best Practices

* Always review generated migrations before applying them
* Never manually edit migration files after they've been applied
* Keep the `atlas.sum` file in version control
* Use descriptive migration names
* Test migrations in a development environment before applying to production

## Troubleshooting

If you encounter issues:

* Verify your database connection string
* Ensure the migrations directory exists
* Check that the `atlas.sum` file is consistent with your migration files
* Use `atlas migrate validate` to check for issues

## Documentation

For more information, refer to the [Atlas documentation](https://atlasgo.io/docs).

## Converting to OpenAPI 3.0.1

### Method 1: Swagger Converter

The conversion to 3.0.0 is because I recently tried to import the interface into the LLMOps plugin, and all interfaces
need the OpenAPI spec. So I looked for a way. Many ways were found, but the quickest and most direct way is to use the
official Swagger converter. Call the interface provided by the converter, or use the page’s test, to convert the
`swagger.json` generated by swag into OpenAPI spec.

- **Input:** `swagger.json` generated by swag.
- **Output:** OpenAPI spec, clearly marked by the first line being:

```json
{
  "openapi": "3.0.1",
  "info": {
    "title": "",
    "version": ""
  },
  "paths": {}
}
```

Previously it was:

```json
{
  "swagger": "2.0",
  "info": {
    "version": "",
    "title": ""
  },
  "paths": {}
}
```

Website: [Swagger Converter](https://converter.swagger.io/#/)

This website can be privately deployed. Deployment method is available
at: [swagger-converter GitHub](https://github.com/swagger-api/swagger-converter)
It is available online at https://converter.swagger.io/ and as
a [docker image](https://hub.docker.com/r/swaggerapi/swagger-converter) e.g.:

```
docker pull swaggerapi/swagger-converter:v1.0.6-SNAPSHOT
docker run -it -p 8080:8080 --name swagger-converter swaggerapi/swagger-converter:v1.0.6-SNAPSHOT
```
